# High Noon Flip

[English version](README.md)

Монетка в стиле вестерна: игрок выбирает Sheriff или Outlaw, револьвер стреляет и
подбрасывает монету. Два режима:

- **Instant** — один бросок, выигрыш ×1.98.
- **Multiply** — каждый угаданный бросок удваивает приз, до ×253.44. Забрать выигрыш
  (cash out) можно в любой момент; одна ошибка — и ставка сгорает.

В папке `prototype/` лежит исходный прототип в одном файле. Это эталон того, как игра
должна выглядеть, звучать и ощущаться. В сборку он не входит.

## Команды

| `npm test`          | Юнит-тесты (Vitest)                                |

Перед коммитом: `npm run typecheck && npm run lint && npm test`.

### Параметры запуска

Параметры передаются в URL так же, как их передаёт оператор казино:
`?lang=de&mode=demo&debug=1&lobbyUrl=https://casino.example`

| Параметр   | Значение                                                           |
| ---------- | ------------------------------------------------------------------ |
| `token`    | Токен сессии; сервер проверяет его у оператора                     |
| `lang`     | Язык и формат чисел: `en`, `ru`, `de`, `pt-BR`…                    |
| `mode`     | `demo` (игровые деньги) или `real`                                 |
| `lobbyUrl` | Куда ведёт кнопка «Домой»; принимаются только http(s)-ссылки       |
| `debug`    | `1` включает инструменты QA; в режиме `real` не включается никогда |

### QA-панель

С `debug=1` в режиме `demo` (с `mode=real` — никогда) у левого края страницы появляется
вкладка **QA**; она или клавиша `` ` `` (на русской раскладке — «ё») открывает панель. Панель
меняет тестовый сервер, а не клиент, поэтому всё, что показывает экран, по-прежнему пришло
из ответа сервера:

- **Next flips** — очередь исходов: Sheriff, Outlaw или выигрыш/проигрыш при любом выборе
  игрока.
- **Errors** — любой код ошибки сервера: до сервера (запрос ничего не меняет) или после
  (сервер засчитал раунд, ответ потерялся — проверка восстановления раунда). Offline —
  падает каждый запрос; задержка сети от 0 до 5 с.
- **Balance** — баланс на сервере. «Update the screen now» сразу пересинхронизирует
  клиент; без галочки о новом балансе узнает следующая ставка, как при изменении баланса
  в другой вкладке.
- **Multiply run** — открыть ран на любой ступени с текущей ставкой или передвинуть
  открытый.
- **Session** — сброс к первому визиту (настройки остаются) или перезагрузка посреди раунда.

Панель — отдельный чанк, его скачивает только `debug=1`. В консоли те же объекты:

```js
hnf.server.forceOutcomes('win', 'lose'); // следующий бросок выиграет, затем проиграет
hnf.server.failNext('NETWORK', 'after'); // сервер засчитает запрос, ответ потеряется
hnf.server.setBalance(50); // баланс 0.50 на сервере — проверить нехватку средств
hnf.model.refresh(); // клиент перечитает баланс и открытый ран
hnf.server.reset(); // сбросить сессию
hnf.scene.turnCoin(); // перевернуть монету, как по тапу
hnf.scene.win(5); // самый большой эффект выигрыша
hnf.settings.set({ ...hnf.settings.get(), speed: 4 }); // турбо со следующего раунда
hnf.audio.play('tick'); // проиграть клип из звукового спрайта
```

### Как проходит раунд

```
idle ──выбор / cash out──▶ requesting ──ответ сервера──▶ revealing ──▶ result ──▶ idle
                               └──ошибка──▶ error ──диалог──▶ idle
```

1. Игрок нажимает Sheriff. `RoundModel` переходит в `requesting`, блокирует кнопки и
   сразу показывает списание ставки с баланса.
2. Модель отправляет запрос через `GameServer`. Сервер списывает ставку, бросает монету,
   считает выигрыш и возвращает исход и новый баланс.
3. Фаза `revealing`: исход уже известен, director дожидается взвода курка (он начался ещё
   в `requesting`), стреляет и отправляет монету на нужную сторону. Выигрыш на балансе
   пока не показан.
4. Монета приземлилась: director вызывает `finishReveal()`, модель переходит в `result`,
   баланс обновляется, появляется штамп WIN или LOSE.
5. Director выдерживает паузу и вызывает `finishResult()`, модель возвращается в `idle`.
   Если рынок требует минимальную длительность раунда (`minRoundMs`), пауза растягивается
   до неё. Скорость 1×/2×/4× меняет все длительности сразу (`game/timing.ts`); где турбо
   запрещено (`turboAllowed: false`), всегда 1×.

Нажатия вне фазы `idle` игнорируются, поэтому двойной тап никогда не отправит две ставки.

### Правила, которым следует код

- **Решает сервер.** Клиент отправляет запрос и показывает ответ. Он никогда не выбирает
  исход и не считает баланс сам: баланс всегда берётся из ответа сервера.
- **Один шов с внешним миром.** Всё общение с сервером идёт через интерфейс `GameServer`.
  Сейчас его реализует `MockServer`; потом появится адаптер к SDK провайдера, и больше
  ничего в игре менять не придётся.
- **Деньги — целые числа в минимальных единицах** (центах) везде. Превращать сумму в текст
  умеет только `shell/money.ts`.
- **Состояние игры живёт в модели, а не в DOM.** Сцена и интерфейс только отображают
  состояние и никогда не меняют его напрямую — только через методы модели.
- **Раунд ждёт анимаций, а не таймеров.** Часы сцены встают вместе со скрытой вкладкой,
  поэтому раунд не «проматывается» в фоне.
- **Арт приходит со своими замерами.** Координаты, измеренные на картинке, лежат в
  `public/assets/images/scene-layout.json` (сцена) или `src/game/ui/art/cylinder.json`
  (барабан) рядом с ней, а не в коде.
- **Ставки присылает оператор.** Барабан — бесконечный: шесть гнёзд показывают любое число
  уровней, подписи меняются на невидимой стороне. Клиент никогда не рассчитывает на шесть.
- **Клавиши:** ← Outlaw, → Sheriff, ↑ ↓ ставка. Зажатая клавиша не повторяется, поэтому не
  может сработать как автоигра.
- **Ни одной строки в коде.** Всё, что читает игрок, — ключ в `src/locales/en.json`.
  Английский лежит в бандле; любой другой язык — маленький чанк, который грузится, только
  если его просит `lang`. Новый язык — это файл `xx.json` рядом с `en.json`; тест упадёт,
  пока в нём нет всех ключей с теми же `{подстановками}`. Нет языка или ключа — будет
  английский.
- **Правила берутся из конфига.** Выплаты, лестница, ставки, RTP и максимальный выигрыш на
  экране правил читаются из `GameConfig` сервера и никогда не вписываются в текст.
- **После непонятной ошибки клиент переспрашивает сервер.** Если связь оборвалась посреди
  ставки, клиент не знает, прошла ли она, поэтому после ошибки заново запрашивает баланс и
  открытую серию.

### Словарь

| Термин         | Значение                                                           |
| -------------- | ------------------------------------------------------------------ |
| RGS            | Remote Game Server — сервер провайдера, где живут RNG и математика |
| RNG            | Генератор случайных чисел (на сервере, сертифицированный)          |
| RTP            | Процент возврата игроку; здесь 99%                                 |
| Minor units    | Сумма в минимальных единицах валюты: 1.98 EUR — это `198`          |
| Open run       | Незавершённая серия Multiply; после перезагрузки она продолжается  |
| Debit / credit | Списание ставки / начисление выигрыша на кошельке оператора        |

## Стек

TypeScript (strict), Vite, PixiJS 8, Preact, Vitest, ESLint, Prettier.
Версии зафиксированы точно в `package.json`.

## Как вести работу

План разбит на шаги в [docs/ROADMAP.md](docs/ROADMAP.md): один шаг — одна задача (или один
чат с Claude). Сделали шаг — отметьте его в ROADMAP и закоммитьте. Код, комментарии и
английский README пишутся на английском, потому что уходят провайдеру; этот файл — для
команды. Меняете структуру проекта — обновите оба README.
